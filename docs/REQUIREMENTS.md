# 要件定義書：TaskHub SaaS 版（Web アプリ）

**バージョン**: v2.0.0-saas
**作成日**: 2026-05-25
**ステータス**: 承認済み
**前バージョン**: v1.3.0（macOS ネイティブアプリ、git 履歴で参照）

---

## 0. 方針転換の背景

本プロダクト TaskHub は当初、macOS ネイティブアプリ（Swift + SwiftUI + SwiftData）として設計されていた（v1.3.0）。本バージョン v2.0.0-saas では **SaaS（Web アプリ）への方針転換** を行う。

### 0.1 方針転換の理由

- マルチデバイス（PC + スマホ）からどこでもアクセスしたい
- macOS 固有機能（Keychain・メニューバー常駐・SwiftData）への依存を解消
- 配布の容易さ（URL アクセス）と更新の即時性
- 個人利用・シングルユーザーの前提は維持

### 0.2 macOS 版（v1.3.0）からの主な変化

| 項目 | macOS 版（v1.3.0） | SaaS 版（v2.0.0-saas） |
|------|-------------------|----------------------|
| 動作環境 | macOS 14 Sonoma+ ネイティブ | モダン Web ブラウザ（PC・スマホ） |
| 永続化 | SwiftData（ローカル DB） | クラウド DB（設計フェーズで確定） |
| 認証情報保管 | macOS Keychain | サーバー側暗号化ストレージ（設計フェーズで確定） |
| アプリログイン | なし（個人 macOS マシン前提） | アクセス制御方式は設計フェーズで決定 |
| 動作モデル | ローカルファースト・完全オフライン | クラウドファースト・オンライン前提 |
| 外部 OAuth | macOS Desktop App フロー | Web OAuth フロー（公開リダイレクト URI） |
| 配布 | 未署名 .dmg | URL アクセス（デプロイ先は設計フェーズで確定） |
| キーボード操作 | ⌘N / ⌘T / ⌘F 等の macOS ショートカット | ブラウザ標準 + Web ショートカット（PC のみ） |
| メニューバー常駐 | あり | なし |
| ファイル保存 | NSSavePanel で .md 出力 | ブラウザのダウンロード API |
| マルチデバイス | 対象外 | 自動的に対応（PC ↔ スマホで同データ） |

### 0.3 維持される本質的価値

- 複数の外部 SaaS（Notion・Google スプレッドシート等）からタスクを取り込み、自分にアサインされたタスクを一元管理
- ステータス・進捗をアプリ内で更新
- 日報・作業報告を Markdown でテンプレートから自動生成
- 連携ツールはプラグイン型で拡張可能な構造

## 1. プロジェクト概要

### 1.1 ゴール

複数の外部 SaaS ツール（Notion・Google スプレッドシート等、将来は JIRA / Linear / Asana 等に拡張）に散らばった自分のアサインタスクを、Web ブラウザ（PC・スマホ）からどこでもアクセスできる単一の場所で統合管理し、日報・作業報告を Markdown で自動生成する個人用 Web アプリケーションを提供する。

### 1.2 対象ユーザー

- 複数の SaaS ツールでタスクを管理しており、横断的に一元管理したい個人開発者・フリーランス・ナレッジワーカー
- PC とスマホを行き来して作業するユーザー
- 自分のタスクを横断的に俯瞰し、報告作業を省力化したいユーザー

### 1.3 提供価値

- 散らばったタスクの「自分ビュー」を Web からどこでも確認
- ステータス・進捗度をアプリ内で一元管理（外部ツールを開かずに更新）
- 日報・作業報告の自動生成による報告作業の削減
- マルチデバイス対応（PC ↔ スマホで同データ）

## 2. 機能要件

### 2.1 コアタスク管理

#### FR-01 プロジェクト / リスト / タスクの CRUD

```
As a ユーザー, I want to プロジェクト → リスト → タスクの3階層で情報を整理したい
So that 大きな目標を小さな実行単位に分解できる

受け入れ基準:
- 新規プロジェクト作成時、サイドバーに名前と色・アイコンが表示される
- プロジェクト配下にリスト、リスト配下にタスクを作成できる
- 削除時は子要素（リスト・タスク・サブタスク）をカスケード削除（確認ダイアログあり）
- ブラウザリロード後・別端末からアクセスしても前回のデータが完全に同期されている
- データ操作は楽観的 UI 更新 + サーバー同期で 200ms 以内に UI に反映される
```

#### FR-02 手動タスク作成（自由入力）

```
As a ユーザー, I want to 外部ツール連携に関係なくアプリ内でタスクを作成したい
So that すべての作業を一箇所で管理できる

受け入れ基準:
- 任意のリストが選択中、ショートカット または「+」ボタンで新規タスク入力フォームが表示される
- タイトル（必須）/ メモ / 期限日 / 優先度 / タグ / ステータス / 進捗度 / 作業時間（h）を設定可能
- タイトルが空の場合は保存できない（バリデーションエラー表示）
- 手動タスクは source: manual として外部タスクと区別できる
```

#### FR-03 タグ管理

```
As a ユーザー, I want to タスクに複数のタグを付けたい
So that プロジェクトをまたいで横断的に絞り込める

受け入れ基準:
- タグの CRUD（名前・色）が設定画面で可能
- 1 タスクに 0〜N 個のタグを紐付け可能
- タグでフィルタすると該当タスクのみが一覧に表示される
```

#### FR-04 ステータス編集

```
As a ユーザー, I want to 一覧でタスクのステータスを直接編集したい
So that 詳細画面を開かずに状態を素早く更新できる

受け入れ基準:
- ステータス値: 未着手 / 進行中 / レビュー中 / 完了 / 保留（固定5値）
- 一覧の該当セルをクリックするとドロップダウンが開く
- ステータスを「完了」に設定すると完了フラグ（isCompleted）が自動的に true になる
- 完了フラグを false に戻すと（チェックを外すと）ステータスは「未着手」に自動リセットされる
- Space キー（PC のみ）で完了フラグをトグル
- スマホでは完了チェックボックスをタップで切替
```

#### FR-05 進捗度（%）編集

```
As a ユーザー, I want to タスクの進捗度を % で記録したい
So that 部分的な進捗を可視化できる

受け入れ基準:
- 進捗度は 0〜100% の整数値
- スライダー UI + 数値入力フィールドの両方で編集可能
- 0 / 25 / 50 / 75 / 100 のクイックボタンを提供
- 進捗度を 100% にすると「ステータスを完了にしますか？」確認ダイアログを表示する
  - 「はい」: ステータスを「完了」に変更し、完了フラグを true にする
  - 「いいえ」: 進捗度 100% のままステータスは変更しない
```

#### FR-06 完了・期限・優先度

```
受け入れ基準:
- 優先度は 低 / 中 / 高 / 緊急 の4段階
- 期限切れタスク（期限日 < 今日 かつ 未完了）は一覧上で視覚的に強調表示（赤字 or アイコン）
- 完了タスク（isCompleted = true）は取り消し線で表示し、表示/非表示の切替が可能
```

#### FR-06b サブタスク管理

```
As a ユーザー, I want to タスクの下にサブタスクを追加したい
So that 大きな作業を細かい手順に分解して管理できる

受け入れ基準:
- 任意のタスクに対してサブタスクを N 個追加できる（階層は タスク > サブタスク の2段まで）
- サブタスクはタイトル（必須）/ 完了フラグ を持つ
- サブタスクの完了状態はタスク詳細画面で個別にトグルできる
- 親タスクの詳細画面でサブタスクの追加・編集・削除・並び替えができる
- すべてのサブタスクが完了になると、親タスクに「完了にしますか？」確認ダイアログを表示する
- レポート生成時に {{today.workLog}} や {{today.plan}} の [sub] として出力される
```

#### FR-06c 本日の進捗画面

```
As a ユーザー, I want to 今日のタスクを一画面で確認・更新したい
So that 日報生成前に作業時間を入力し、正確な工数を記録できる

受け入れ基準:
- サイドバー（PC）/ タブ（スマホ）に「今日」の固定ビューを設ける
- 期限日が今日 または ステータスが「進行中」のタスクを自動収集して表示する
- 一覧上で以下を直接編集できる:
  - ステータス
  - 進捗度（%）
  - 作業時間（h）：その日に何時間作業したかを 0.5h 単位で入力
- タスクをタップ/クリックするとサブタスク一覧も展開表示される
- 合計作業時間（今日の全タスクの作業時間の合計）を画面上部に表示する
- この画面から直接「作業開始報告を生成」「業務日報を生成」ボタンを呼び出せる
```

#### FR-07 キーボードショートカット（PC のみ・スマホは UI ボタンで代替）

| ショートカット | 操作 |
|--------------|------|
| `c` または `n` | 新規タスク追加 |
| Space | 完了トグル |
| `/` | 検索フォーカス |
| Delete / Backspace | 選択タスク削除 |
| `g` then `t` | 今日ビュー |
| `g` then `i` | インボックス |
| ↑↓ | タスク選択移動 |

> 具体的なバインドは設計フェーズで再検討する。

#### FR-08 ダーク / ライトテーマ

```
受け入れ基準:
- OS / ブラウザの prefers-color-scheme に追従する
- ユーザーが手動で Light / Dark / Auto を選択可能
- 切替は再読み込みなしで即時反映される
```

#### FR-09 永続化（クラウド DB）

```
受け入れ基準:
- 全データはサーバー側 DB に保存される（ブラウザストレージは UI キャッシュ用途のみ）
- 書き込み失敗時はトーストで通知し、リトライ可能
- 別端末（スマホ↔PC）で開いている場合の反映方式は設計フェーズで決定
  （リアルタイム購読 / ポーリング / 手動リロード から選択）
```

### 2.2 検索・フィルタ・整理

#### FR-10 全文検索

```
受け入れ基準:
- タイトル・メモ・タグ・サブタスクのタイトルを横断したインクリメンタル検索
- 5,000 件のタスクに対して p95 < 300ms（ネットワーク往復含む）で結果表示
- 検索結果から該当プロジェクト/リストへジャンプ可能
- DB 側のフルテキストインデックスを利用する（具体技術は設計フェーズで決定）
```

#### FR-11 並び替え・フィルタ

```
受け入れ基準:
- 並び替え条件: 作成日 / 期限 / 優先度 / 進捗度 / ステータス（昇順/降順）
- フィルタ: ステータス / タグ / 作成元（手動 / ツール種別 / 接続名）/ 期限（今日/今週/期限切れ）
- 設定はサーバー側に保存し、別端末でも引き継ぐ
```

#### FR-12 JSON エクスポート / インポート

```
受け入れ基準:
- 全プロジェクト/リスト/タスク/サブタスク/タグ/作業時間/コネクション設定（認証情報を除く）を JSON 形式でエクスポート
- API トークン等の認証情報はセキュリティ上エクスポートに含めない
- エクスポートはブラウザのファイルダウンロードで提供
- JSON からのインポートで全データを復元可能（認証情報は再入力が必要である旨を通知）
- バックアップ目的のユーザー操作として提供
```

### 2.3 外部タスクインポート

> **設計方針**: 連携ツールはプラグイン型で拡張可能な構造とする。MVP では Notion / Google スプレッドシートを実装し、将来は JIRA・Linear・Asana・Trello・GitHub Issues 等を追加できる設計とする。1 つのツール種別に対して N 個の接続（プロジェクト）を設定可能とする。同期処理は **サーバー側** で実行する。

#### FR-13 インテグレーションカタログ UI

```
As a ユーザー, I want to 利用可能な連携ツールを一覧で確認し、使いたいものを選んで追加したい
So that アプリを拡張していく感覚で新しいツールを追加できる

受け入れ基準:
- 設定画面 > インテグレーションタブに「利用可能なツール」カタログを表示する
- カタログにはツールのアイコン・名前・ステータス（実装済み / Coming Soon）を表示する
- MVP で実装済みのツール: Notion / Google スプレッドシート
- Coming Soon として表示するツール（UI のみ・接続不可）: JIRA / Linear / Asana / Trello / GitHub Issues
- Coming Soon のツールは選択するとモーダルで「今後対応予定です」と表示する
- 将来ツールを追加する際は、このカタログにエントリを追加するだけで UI に反映される（ハードコード不要）
```

#### FR-14 接続（コネクション）管理

```
As a ユーザー, I want to 1 つのツールに対して複数の接続先（プロジェクト）を登録したい
So that 複数の Notion データベースや複数の Google スプレッドシートを別々に同期できる

受け入れ基準:
- 各ツールに対して「+ 接続を追加」ボタンで接続先を N 個登録できる
- 各接続は以下のプロパティを持つ:
  - 接続名（ユーザーが任意に設定: 例「仕事用 Notion」「クライアント A シート」）
  - ツール種別（notion / gsheet 等）
  - 認証情報（サーバー側の暗号化ストレージに保管・クライアントへは返さない）
  - 自分の識別子（ツール上で "自分" を特定するための情報）
    - Notion: 自分の Notion ユーザー ID
    - Google スプレッドシート: 担当者列の名前 or メールアドレス
  - ツール固有の設定（Notion: データベース ID / GSheet: スプレッドシート ID + シート名 + 列マッピング 等）
  - 有効 / 無効フラグ
- 各接続の一覧で名前・ステータス・最終同期日時を確認できる
- 接続の編集・削除・有効/無効切替が可能
- 接続を削除してもローカル取込済みタスクは保持する（削除しない）
```

#### FR-15 一括同期（全接続）

```
As a ユーザー, I want to 同期ボタン1つで有効な全接続からタスクを取得したい
So that ツールや接続先ごとに操作せず一度で最新状態を取り込める

受け入れ基準:
- ツールバーの「同期」ボタン押下で、サーバー側で有効な全接続への取得を順次実行する（1接続ずつ処理・Vercel Hobby の実行時間制限対応のため。DESIGN.md ADR-004 参照）
- 各接続は「自分の識別子」を使い、自分にアサインされたタスクのみを取得する
  - Notion: People プロパティに自分の Notion ユーザー ID が含まれるページのみ取得
  - Google スプレッドシート: 担当者列に自分の名前 or メールが含まれる行のみ取得
- 同期中はプログレスインジケータを表示（接続名と進捗状況を表示）
- 同期進捗はサーバーからクライアントへ配信する（配信方式は設計フェーズで決定）
- 成功した接続の分だけ即座にインボックスへ反映する
- 失敗した接続はトーストとサマリーパネルでエラー内容を通知する（成功分はロールバックしない）
- 最終同期日時と「成功 N / 失敗 M 接続」のサマリーをフッターに表示する
- 同期中に再度ボタンを押すと「中断」に切り替わる（進行中ジョブをキャンセル）
- レート制限はサーバー側で制御する（Notion 3 req/sec、GSheet 60 req/min）
- 同期ジョブの実行方式（同期レスポンス内 / バックグラウンドジョブ）は設計フェーズで決定
```

#### FR-16 インボックス（取込先リスト）

```
As a ユーザー, I want to 外部から取得したタスクを専用のリストで受け取りたい
So that どのツール・接続由来かに関わらず未処理タスクを一箇所で確認できる

受け入れ基準:
- インボックスはいずれのプロジェクトにも属さない独立したリストとして存在する（サイドバー最上部に固定表示）
- アプリ初期状態で「インボックス」が存在する（削除・リネーム不可）
- 外部から取得した全タスクは接続・ツール種別に関わらずインボックスに追加される
- インボックスのタスクは任意のリストへドラッグ&ドロップ（PC）または移動メニュー（スマホ）で移動できる
- 移動後のタスクは source バッジ（ツール名 + 接続名）を保持する
- 再同期時にすでに移動済みのタスクは移動先リストで更新される（インボックスへ戻らない）
```

#### FR-17 同期時の競合・削除ルール

```
受け入れ基準:
【更新】
- 再同期時: 外部のタイトル・メモ・期限は上書き更新する
- ローカルで編集したステータス・進捗度は保持する（外部の値で上書きしない）

【外部側での削除】
- 外部ツール側でタスクが削除されていた場合、確認ダイアログを表示する
  - 「削除する」: アプリからも削除
  - 「残す」: アーカイブ状態（グレーアウト）として保持
- ダイアログは削除対象タスクの一覧を表示し、一括選択が可能

【サブタスクの同期】
- 外部ツール側にサブタスク相当の情報がある場合、取込時にサブタスクとして追加する
- 外部ツールにサブタスクの概念がない場合（Google スプレッドシート等）はサブタスクを生成しない
- 再同期時: 外部のサブタスクは上書き更新する。ローカルで追加したサブタスクは保持する

【新規取得】
- 前回同期時に存在しなかったタスクをインボックスへ追加する
- 同一タスクの重複追加は connectionId + externalId の複合キーで防ぐ
```

#### FR-18 認証・セキュリティ（SaaS 版）

```
受け入れ基準:
- すべての API トークン / OAuth トークン / Refresh Token はサーバー側の暗号化ストレージに保存する（具体機構は設計フェーズで決定）
- 認証情報はクライアント JS に絶対に渡さない（クライアントは「設定済み/未設定」の状態のみ知る）
- 設定 UI ではシークレットを SecureField（パスワード型入力欄）で受け取り、即座にサーバーに POST
- 各接続に「接続テスト」ボタンを設け、疎通確認結果をインライン表示する
- Notion Integration Token 方式での接続
- Google OAuth 2.0 Web Server フロー（client_secret はサーバー側のみ保持・PKCE 推奨）
- リダイレクト URI は固定 URL を使用
- Notion API レート制限（3 req/sec）に対応した Exponential Backoff リトライ
- Google Sheets API レート制限（60 req/min）に対応した制御
- 通信はすべて HTTPS（TLS 1.2 以上）
```

### 2.4 日報・作業報告

> **設計方針**: テンプレートの管理（設定）とレポートの生成（日常操作）を分離する。テンプレートは一度作成すれば毎回再利用でき、生成時はテンプレート選択 →「生成」ボタン → コピペ の3ステップで完結する。

#### FR-19 レポートテンプレート管理

```
As a ユーザー, I want to 自分のフォーマットに合わせたテンプレートを作成・保存したい
So that 毎回ゼロから書かずに済み、報告作業を省力化できる

受け入れ基準:
- テンプレートの CRUD（作成・編集・削除・複製）ができる
- 各テンプレートは以下のプロパティを持つ:
  - テンプレート名（例: 「毎日の日報」「週次報告」）
  - 対象期間種別（今日 / 今週 / 今月 / カスタム期間）
  - 本文（自由テキスト＋変数プレースホルダーの組み合わせ）
- アプリはデフォルトテンプレートを2種プリセットで提供する
- デフォルトテンプレートは編集・削除が可能

デフォルトテンプレート①「作業開始報告」（対象期間: 今日）:
  作業開始します。

  ■今日の予定
  {{today.plan}}

  ■担当タスク一覧
  {{assigned.tasks}}

デフォルトテンプレート②「業務日報」（対象期間: 今日）:
  【{{date}}業務報告】
  ■今日やったこと: 計{{today.totalHours}}h
  {{today.workLog}}

  ■勉強になったこと


  ■明日やること
  {{next.tasks}}


  ■連絡事項


  ■感想


テンプレートエディター:
- テキストエリアで本文を自由に編集できる
- エディター横の変数パネルに使用可能な変数を一覧表示する
- 変数をクリックするとカーソル位置に自動挿入される（シンタックス入力不要）
- プレビューボタンで実際のデータを差し込んだ表示を確認できる
```

#### FR-20 差し込み変数

```
テンプレートで使用できる変数（プレースホルダー）の仕様:

| 変数 | 差し込まれる内容 |
|------|----------------|
| {{date}} | 生成日（例: 2026/05/25） |
| {{period.start}} | 対象期間の開始日 |
| {{period.end}} | 対象期間の終了日 |
| {{today.totalHours}} | 今日の合計作業時間（例: 8.0） |
| {{today.workLog}} | 今日の作業ログ（プロジェクト別・工数付き・サブタスク含む） |
| {{today.plan}} | 今日予定のタスク一覧（期限日が今日 または ステータスが進行中、プロジェクト別・サブタスク含む） |
| {{today.completed}} | 今日完了したタスク一覧（箇条書き） |
| {{today.inProgress}} | 今日作業中のタスク一覧（箇条書き） |
| {{assigned.tasks}} | 担当タスク一覧（プロジェクト別・進捗%付き） |
| {{next.tasks}} | 未着手・次にやるタスク一覧（期限が近い順） |
| {{projects.summary}} | プロジェクト別の完了数・進捗率サマリー |
| {{period.completed}} | 対象期間内に完了したタスク一覧（週報・月報用） |

出力フォーマット仕様:
{{today.workLog}} の出力例（プロジェクト間に空行なし・コンパクト表示）:

  DWAI 1.0h
  ● Vercelについて調査
  AIエージェント課題 6.0h
  ● 専用アプリ開発
    ○ ClaudeCode自走基盤設定
    ○ 開発
    ○ Vercel設定

{{today.plan}} の出力例（プロジェクト間に空行）:
  DWAI
  ● Vercelについて調査

  AIエージェント課題
  ● 専用アプリ開発
    ○ ClaudeCode自走基盤設定
    ○ Vercel設定

{{assigned.tasks}} の出力例（プロジェクト間に空行）:
  DWAI
  ● Vercelについて調査[50%]

  AIエージェント課題
  ● 専用アプリ開発[30%]

受け入れ基準:
- 変数は本文中のどこにでも配置できる
- 該当するタスクが0件の場合は「（なし）」と出力する
- 変数以外の自由テキストはそのまま出力される
- 作業時間が未入力のタスクは時間表示を省略する
```

#### FR-21 レポート生成

```
As a ユーザー, I want to テンプレートを選んでボタンを押すだけでレポートを生成したい
So that 日常の報告作業を最小限の操作で完了できる

受け入れ基準:
- レポート生成画面でテンプレートをドロップダウンから選択する
- 対象期間種別が「カスタム」のテンプレートは期間（開始日・終了日）を指定できる
- 「生成」ボタンを押すとテンプレートにタスクデータが差し込まれ、プレビューに表示される
- プレビュー上で内容を手動編集できる（生成後の微調整用）
- 出力オプション:
  - クリップボードへコピー（Web Clipboard API）
  - Markdown ファイルとして保存（ブラウザダウンロード、ファイル名: YYYY-MM-DD-{テンプレート名}.md）
- 本日の進捗画面（FR-06c）の「作業開始報告を生成」「業務日報を生成」ボタンからも呼び出せる
  （対応テンプレートが自動選択された状態で開く）
```

#### FR-22 レポート履歴

```
受け入れ基準:
- 生成したレポートはクラウド DB に自動保存（生成日時・使用テンプレート名・本文を記録）
- 履歴一覧から過去のレポートを再表示・再編集・再出力が可能
- 履歴はテンプレート名や期間で絞り込める
- 別端末からも履歴を閲覧可能
```

## 3. 非機能要件

### 3.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 初回ページロード（LCP） | p95 < 2.5 秒（4G 想定） |
| ページ間ナビゲーション | p95 < 300ms |
| タスク一覧描画（1,000 件） | 仮想スクロールで滑らかに動作 |
| 全文検索（5,000 件、ネットワーク往復含む） | p95 < 300ms |
| 同期処理（1 接続あたり 100 タスク） | サーバー処理 5 秒以内 |
| API レスポンス（CRUD） | p95 < 200ms（サーバー処理時間） |

### 3.2 セキュリティ

- すべての通信は HTTPS（TLS 1.2 以上）
- 外部ツールのトークン・client_secret はサーバー側で暗号化保管（クライアントへ非送信）
- 入力はサーバー側でスキーマ検証する（具体ライブラリは設計フェーズで決定）
- SQL Injection / XSS / CSRF 対策（フレームワーク標準機構を利用）
- API レベルでレート制限を適用
- ログにトークン・個人情報を含めない
- アプリ自体のアクセス制御方式は **設計フェーズで決定**（Q1 参照）
- 監査ログ: 接続作成・削除・OAuth 認可フローを記録

### 3.3 可用性

- 想定稼働率: 99.5%（個人用途のため SLA は緩め）
- 外部 SaaS（Notion / Google）障害時もアプリ本体は動作（取込のみ失敗扱い）
- 各外部 API のレート制限に対応したリトライ（Exponential Backoff）
- DB バックアップ: 日次自動バックアップを取得（具体機構は設計フェーズで決定）
- JSON エクスポートによりユーザー手動バックアップも可能

### 3.4 スケーラビリティ

- 想定ユーザー: 1名（個人利用）
- 最大データ量: プロジェクト 50 / リスト 500 / タスク 10,000 / レポート履歴 1,000 件
- 同時セッション: PC + スマホの 2 セッション程度

### 3.5 互換性

- ブラウザ: 最新 2 バージョンの Chrome / Safari / Edge / Firefox
- モバイル: iOS Safari 17+ / Android Chrome 最新版
- 画面幅: 360px〜（スマホ縦持ち）から 1920px+（PC）までレスポンシブ対応

### 3.6 アクセシビリティ

- WCAG 2.1 Level AA 準拠を目標
- キーボードのみで PC の全主要操作が完結
- スマホはタッチ操作に最適化
- 主要 UI に適切な aria 属性を付与

### 3.7 国際化

- 言語: 日本語 / 英語（ブラウザ言語に追従、設定で上書き可能）
- 日付・時刻フォーマット: ロケール追従

### 3.8 観測性

- エラーログ: サーバー側で構造化ログ出力（具体機構は設計フェーズで決定）
- クライアントエラー: エラートラッキングサービス連携を検討（任意）
- 同期ジョブの実行履歴・失敗ログを参照可能にする

## 4. スコープ境界

### 4.1 MVP In（このフェーズで実装）

- プロジェクト / リスト / タスク / サブタスクの CRUD
- タグ管理（CRUD・タスク紐付け・横断フィルタ）
- ステータス編集（5値）・進捗度・優先度・期限・メモ・作業時間
- 手動タスク作成
- 検索・並び替え・フィルタ
- JSON エクスポート / インポート
- PC 向けキーボードショートカット
- ダーク / ライトテーマ
- クラウド DB 永続化（マルチデバイス対応）
- インテグレーションカタログ UI（実装済み + Coming Soon ツールを表示）
- Notion インポート（Integration Token・N 接続対応・サーバー側同期）
- Google スプレッドシートインポート（Web OAuth 2.0・N 接続対応・サーバー側同期）
- 接続管理 UI（追加・編集・削除・有効/無効）
- 手動同期（同期ボタン押下でサーバー側ジョブ起動）
- 同期進捗のリアルタイム表示
- 本日の進捗画面
- レポートテンプレート管理（CRUD・デフォルト2種プリセット）
- 差し込み変数クリック挿入エディター
- レポート生成（テンプレート選択 → 生成 → クリップボード / Markdown ダウンロード）
- レポート履歴（クラウド保存）
- レスポンシブ UI（PC + スマホ）

### 4.2 将来フェーズ

- 追加ツールの実装（JIRA / Linear / Asana / Trello / GitHub Issues 等）
- 自動同期（定期バックグラウンド実行・cron / スケジューラ）
- 双方向同期（ローカル編集を外部ツールに書き戻し）
- Slack 投稿連携
- Notion ページへの投稿
- メール送信
- カスタムステータス値

- プッシュ通知
- オフライン編集対応（ローカルキュー + 再接続時同期）

### 4.3 完全対象外（このプロダクトの範囲外）

- マルチテナント SaaS としての商用提供（個人利用前提）
- 複数ユーザー対応（チーム機能・タスク共有・コラボレーション）

- AI による自動分類・要約
- ネイティブモバイルアプリ（iOS / Android）
- ネイティブデスクトップアプリ（macOS / Windows / Linux）

## 6. 用語定義

| 用語 | 定義 |
|------|------|
| プロジェクト | タスクをグループ化する最上位の概念 |
| リスト | プロジェクト配下のタスクグループ |
| インボックス | 外部から取得したタスクの受け取り専用リスト。固定的に存在し削除・リネーム不可 |
| タスク | 実行可能な作業単位。配下にサブタスクを持てる |
| サブタスク | タスクの配下にある細かい作業単位 |
| 作業時間 | その日にタスクに費やした時間（h単位、0.5h刻み） |
| 完了フラグ | タスクの完了/未完了を示すブール値。ステータス「完了」と連動 |
| タグ | プロジェクト横断でタスクを分類するラベル |
| ステータス | タスクの進行状態（未着手/進行中/レビュー中/完了/保留） |
| 進捗度 | 0〜100% で表現するタスクの完了割合 |
| インテグレーション | 外部ツールとの連携機能の総称 |
| コネクション（接続） | インテグレーション内の具体的な接続設定1件 |
| 外部タスク | 外部ツール（インテグレーション経由）から取得したタスク |
| 手動タスク | アプリ内で直接作成したタスク |
| レポートテンプレート | 差し込み変数を含む再利用可能なレポートのひな形 |
| 差し込み変数 | テンプレート内でタスクデータを自動展開するプレースホルダー |
| 日報 | 当日の完了・進行中タスクをまとめたレポート |
| 作業報告 | 指定期間の完了タスクを集計したレポート |
