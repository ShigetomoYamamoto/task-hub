# 要件定義書：タスク管理デスクトップアプリ

**バージョン**: 1.3.0  
**作成日**: 2026-05-23  
**ステータス**: 承認済み

---

## 1. プロジェクト概要

### 1.1 ゴール

macOS ネイティブアプリとして、複数の外部ツール（Notion・Google スプレッドシート等、将来は JIRA/Linear/Asana 等に拡張）に分散したアサインタスクを一元管理し、ステータス・進捗を更新しながら日報・作業報告を Markdown で出力できるデスクトップアプリを提供する。

### 1.2 対象ユーザー

- 複数の SaaS ツールでタスクを管理しており、自分のタスクを横断的に一元管理したい個人開発者・フリーランス・ナレッジワーカー
- macOS をメイン業務環境としているユーザー
- 自分のタスクを横断的に俯瞰し、報告作業を省力化したいユーザー

### 1.3 提供価値

- 散らばったタスクの「自分ビュー」を一画面で確認
- ステータス・進捗度をローカルで一元管理（外部ツールを開かずに更新）
- 日報・作業報告の自動生成による報告作業の削減
- ローカルファースト設計（オフライン完全動作）

## 2. 機能要件

### 2.1 コアタスク管理

#### FR-01 プロジェクト / リスト / タスクの CRUD

```
As a ユーザー, I want to プロジェクト → リスト → タスクの3階層で情報を整理したい
So that 大きな目標を小さな実行単位に分解できる

受け入れ基準:
- Given プロジェクトが存在しない状態で、when 「新規プロジェクト」を作成すると、
  then サイドバーにプロジェクト名と色/アイコンが表示される
- Given プロジェクトが選択中、when リストを追加できる
- Given リストが選択中、when タスクを追加できる
- Given 任意の要素で、when 編集/削除を行うと、then 子要素（リスト・タスク・サブタスク）はカスケード削除（確認ダイアログあり）
- Given アプリ再起動後、then 前回のデータが完全に復元される
```

#### FR-02 手動タスク作成（自由入力）

```
As a ユーザー, I want to 外部ツール連携に関係なくアプリ内でタスクを作成したい
So that すべての作業を一箇所で管理できる

受け入れ基準:
- Given 任意のリストが選択中、when ⌘N またはボタンを押すと、then 新規タスク入力フォームが表示される
- タイトル（必須）/ メモ / 期限日 / 優先度 / タグ / ステータス / 進捗度 / 作業時間（h）を設定可能
- タイトルが空の場合は保存できない（バリデーションエラー表示）
- 手動タスクは source: manual として外部タスクと区別できる
```

#### FR-03 タグ管理

```
As a ユーザー, I want to タスクに複数のタグを付けたい
So that プロジェクトをまたいで横断的に絞り込める

受け入れ基準:
- タグの CRUD（名前・色）が設定画面で可能
- 1 タスクに 0〜N 個のタグを紐付け可能
- タグでフィルタすると該当タスクのみが一覧に表示される
```

#### FR-04 ステータス編集

```
As a ユーザー, I want to 一覧でタスクのステータスを直接編集したい
So that 詳細画面を開かずに状態を素早く更新できる

受け入れ基準:
- ステータス値: 未着手 / 進行中 / レビュー中 / 完了 / 保留（固定5値）
- 一覧の該当セルをクリックするとドロップダウンが開く
- ステータスを「完了」に設定すると完了フラグ（isCompleted）が自動的に true になる
- 完了フラグを false に戻すと（チェックを外すと）ステータスは「未着手」に自動リセットされる
- Space キーで完了フラグをトグル（true → ステータスが「完了」、false → ステータスが「未着手」）
```

#### FR-05 進捗度（%）編集

```
As a ユーザー, I want to タスクの進捗度を % で記録したい
So that 部分的な進捗を可視化できる

受け入れ基準:
- 進捗度は 0〜100% の整数値
- スライダー UI + 数値入力フィールドの両方で編集可能
- 0 / 25 / 50 / 75 / 100 のクイックボタンを提供
- 進捗度を 100% にすると「ステータスを完了にしますか？」確認ダイアログを表示する
  - 「はい」: ステータスを「完了」に変更し、完了フラグを true にする
  - 「いいえ」: 進捗度 100% のままステータスは変更しない
```

#### FR-06 完了・期限・優先度

```
受け入れ基準:
- 優先度は 低 / 中 / 高 / 緊急 の4段階
- 期限切れタスク（期限日 < 今日 かつ 未完了）は一覧上で視覚的に強調表示（赤字 or アイコン）
- 完了タスク（isCompleted = true）は取り消し線で表示し、表示/非表示の切替が可能
```

#### FR-06b サブタスク管理

```
As a ユーザー, I want to タスクの下にサブタスクを追加したい
So that 大きな作業を細かい手順に分解して管理できる

受け入れ基準:
- 任意のタスクに対してサブタスクを N 個追加できる（階層は タスク > サブタスク の2段まで）
- サブタスクはタイトル（必須）/ 完了フラグ を持つ
- サブタスクの完了状態はタスク詳細画面で個別にトグルできる
- 親タスクの詳細画面でサブタスクの追加・編集・削除・並び替えができる
- すべてのサブタスクが完了になると、親タスクに「完了にしますか？」確認ダイアログを表示する
- レポート生成時に {{today.workLog}} や {{today.plan}} の [sub] として出力される
```

#### FR-06c 本日の進捗画面

```
As a ユーザー, I want to 今日のタスクを一画面で確認・更新したい
So that 日報生成前に作業時間を入力し、正確な工数を記録できる

受け入れ基準:
- サイドバーに「今日」の固定ビューを設ける（⌘T でフォーカス）
- 期限日が今日 または ステータスが「進行中」のタスクを自動収集して表示する
- 一覧上で以下を直接編集できる:
  - ステータス
  - 進捗度（%）
  - 作業時間（h）：その日に何時間作業したかを 0.5h 単位で入力
- タスクをクリックするとサブタスク一覧も展開表示される
- 合計作業時間（今日の全タスクの作業時間の合計）を画面上部に表示する
- この画面から直接「作業開始報告を生成」「業務日報を生成」ボタンを呼び出せる
```

#### FR-07 キーボードショートカット

| ショートカット | 操作 |
|--------------|------|
| ⌘N | 新規タスク追加 |
| Space | 完了トグル |
| ⌘F | 検索フォーカス |
| ⌘⌫ | 選択タスク削除 |
| ⌘, | 設定画面を開く |
| ⌘T | 今日ビューにフォーカス |
| ↑↓ | タスク選択移動 |

#### FR-08 ダーク / ライトテーマ連動

```
受け入れ基準:
- macOS のシステム設定変更時、アプリ再起動なしでテーマが切り替わる
- トラフィックライト（赤/黄/緑）など macOS 標準 UI 要素を維持
```

#### FR-09 ローカル永続化

```
受け入れ基準:
- SwiftData による全データのローカル永続化
- アプリ強制終了後も直前までの編集が保持される
- ストレージ書き込み失敗時はユーザーに通知
```

### 2.2 検索・フィルタ・整理

#### FR-10 全文検索

```
受け入れ基準:
- タイトル・メモ・タグ・サブタスクのタイトルを横断したインクリメンタル検索
- 5,000 件のタスクに対して p95 < 200ms で結果表示
- 検索結果から該当プロジェクト/リストへジャンプ可能
```

#### FR-11 並び替え・フィルタ

```
受け入れ基準:
- 並び替え条件: 作成日 / 期限 / 優先度 / 進捗度 / ステータス（昇順/降順）
- フィルタ: ステータス / タグ / 作成元（手動 / ツール種別 / 接続名）/ 期限（今日/今週/期限切れ）
- 設定はアプリ再起動後も保持
```

#### FR-12 JSON エクスポート / インポート

```
受け入れ基準:
- 全プロジェクト/リスト/タスク/サブタスク/タグ/作業時間/コネクション設定（認証情報を除く）を JSON 形式でエクスポート
- API トークン等の認証情報はセキュリティ上エクスポートに含めない（Keychain のみに保管）
- JSON からのインポートで全データを復元可能（認証情報は再入力が必要である旨を通知）
- バックアップ目的のユーザー操作として提供
```

### 2.3 外部タスクインポート

> **設計方針**: 連携ツールはプラグイン型で拡張可能な構造とする。MVP では Notion / Google スプレッドシートを実装し、将来は JIRA・Linear・Asana・Trello・GitHub Issues 等を追加できる設計とする。1 つのツール種別に対して N 個の接続（プロジェクト）を設定可能とする。

#### FR-13 インテグレーションカタログ UI

```
As a ユーザー, I want to 利用可能な連携ツールを一覧で確認し、使いたいものを選んで追加したい
So that アプリを拡張していく感覚で新しいツールを追加できる

受け入れ基準:
- 設定画面（⌘,）> インテグレーションタブに「利用可能なツール」カタログを表示する
- カタログにはツールのアイコン・名前・ステータス（実装済み / Coming Soon）を表示する
- MVP で実装済みのツール: Notion / Google スプレッドシート
- Coming Soon として表示するツール（UIのみ・接続不可）: JIRA / Linear / Asana / Trello / GitHub Issues（将来追加予定の候補として表示）
- Coming Soon のツールは選択するとモーダルで「今後対応予定です」と表示する
- 将来ツールを追加する際は、このカタログにエントリを追加するだけで UI に反映される（ハードコード不要）
```

#### FR-14 接続（コネクション）管理

```
As a ユーザー, I want to 1 つのツールに対して複数の接続先（プロジェクト）を登録したい
So that 複数の Notion データベースや複数の Google スプレッドシートを別々に同期できる

受け入れ基準:
- 各ツールに対して「+ 接続を追加」ボタンで接続先を N 個登録できる
- 各接続は以下のプロパティを持つ:
  - 接続名（ユーザーが任意に設定: 例「仕事用 Notion」「クライアント A シート」）
  - ツール種別（notion / gsheet 等）
  - 認証情報（Keychain に保管）
  - 自分の識別子（ツール上で "自分" を特定するための情報。ツールごとに形式が異なる）
    - Notion: 自分の Notion ユーザー ID
    - Google スプレッドシート: 担当者列の名前 or メールアドレス
    - ※将来ツール追加時も同様に「自分の識別子」フィールドを設ける
  - ツール固有の設定（Notion: データベース ID / GSheet: スプレッドシート ID + シート名 + 担当者列 等）
  - 有効 / 無効フラグ
- 各接続の一覧で名前・ステータス・最終同期日時を確認できる
- 接続の編集・削除・有効/無効切替が可能
- 接続を削除してもローカルの取込済みタスクは保持する（削除しない）
```

#### FR-15 一括同期（全接続）

```
As a ユーザー, I want to 同期ボタン1つで有効な全接続からタスクを取得したい
So that ツールや接続先ごとに操作せず一度で最新状態を取り込める

受け入れ基準:
- ツールバーの「同期」ボタン押下で、有効な全接続への取得を並列実行する
- 各接続は「自分の識別子（FR-14）」を使い、自分にアサインされたタスクのみを取得する
  - Notion: People プロパティに自分の Notion ユーザー ID が含まれるページのみ取得
  - Google スプレッドシート: 担当者列に自分の名前 or メールが含まれる行のみ取得
  - ※他ツール追加時も同様に「アサイン判定ロジック」をプロバイダーごとに実装する
- 自分にアサインされていないタスクは取得・表示しない
- 同期中はプログレスインジケータを表示（接続名と進捗状況を表示）
- 成功した接続の分だけ即座にインボックスへ反映する
- 失敗した接続はトーストとサマリーパネルでエラー内容を通知する（成功分はロールバックしない）
- 最終同期日時と「成功 N / 失敗 M 接続」のサマリーをフッターに表示する
- 同期中に再度ボタンを押すと「中断」に切り替わる（進行中リクエストをキャンセル）
```

#### FR-16 インボックス（取込先リスト）

```
As a ユーザー, I want to 外部から取得したタスクを専用のリストで受け取りたい
So that どのツール・接続由来かに関わらず未処理タスクを一箇所で確認できる

受け入れ基準:
- インボックスはいずれのプロジェクトにも属さない独立したリストとして存在する（サイドバーの最上部に固定表示）
- アプリ初期状態で「インボックス」が存在する（削除・リネーム不可）
- 外部から取得した全タスクは接続・ツール種別に関わらずインボックスに追加される
- インボックスのタスクは任意のリストへドラッグ&ドロップで移動できる
- 移動後のタスクは source バッジ（ツール名 + 接続名）を保持する
- 再同期時にすでに移動済みのタスクは移動先リストで更新される（インボックスへ戻らない）
```

#### FR-17 同期時の競合・削除ルール

```
受け入れ基準:
【更新】
- 再同期時: 外部のタイトル・メモ・期限は上書き更新する
- ローカルで編集したステータス・進捗度は保持する（外部の値で上書きしない）

【外部側での削除】
- 外部ツール側でタスクが削除されていた場合、確認ダイアログを表示する
  - 「削除する」: アプリからも削除
  - 「残す」: アーカイブ状態（グレーアウト）として保持
- ダイアログは削除対象タスクの一覧を表示し、一括選択が可能

【サブタスクの同期】
- 外部ツール側にサブタスク相当の情報がある場合、取込時にサブタスクとして追加する
- 外部ツールにサブタスクの概念がない場合（Google スプレッドシート等）はサブタスクを生成しない
- 再同期時: 外部のサブタスクは上書き更新する。ローカルで追加したサブタスクは保持する

【新規取得】
- 前回同期時に存在しなかったタスクをインボックスへ追加する
- 同一タスクの重複追加は connectionId + externalId の複合キーで防ぐ
```

#### FR-18 認証・セキュリティ

```
受け入れ基準:
- すべての API トークン / OAuth トークン / Webhook URL は macOS Keychain に保存（平文禁止）
- 設定 UI ではシークレットをマスク表示（入力欄は SecureField）
- 各接続に「接続テスト」ボタンを設け、疎通確認結果をインライン表示する
- Notion API レート制限（3 req/sec）に対応した Exponential Backoff リトライ実装
- Google OAuth 2.0 Desktop App フローでのトークン取得・リフレッシュ実装
```

### 2.4 日報・作業報告

> **設計方針**: テンプレートの管理（設定）とレポートの生成（日常操作）を分離する。テンプレートは一度作成すれば毎回再利用でき、生成時はテンプレート選択 →「生成」ボタン → コピペ の3ステップで完結する。

#### FR-19 レポートテンプレート管理

```
As a ユーザー, I want to 自分のフォーマットに合わせたテンプレートを作成・保存したい
So that 毎回ゼロから書かずに済み、報告作業を省力化できる

受け入れ基準:
- テンプレートの CRUD（作成・編集・削除・複製）ができる
- 各テンプレートは以下のプロパティを持つ:
  - テンプレート名（例: 「毎日の日報」「週次報告」）
  - 対象期間種別（今日 / 今週 / 今月 / カスタム期間）
  - 本文（自由テキスト＋変数プレースホルダーの組み合わせ）
- アプリはデフォルトテンプレートを2種プリセットで提供する
- デフォルトテンプレートは編集・削除が可能

デフォルトテンプレート①「作業開始報告」（対象期間: 今日）:
  作業開始します。

  ■今日の予定
  {{today.plan}}

  ■担当タスク一覧
  {{assigned.tasks}}

  ※ {{today.plan}} の出力フォーマット（プロジェクト間に空行）:
    プロジェクト名
    ● タスク名
      ○ サブタスク名

    プロジェクト名
    ● タスク名

  ※ {{assigned.tasks}} の出力フォーマット（プロジェクト間に空行）:
    プロジェクト名
    ● タスク名[進捗%]

    プロジェクト名
    ● タスク名[進捗%]

デフォルトテンプレート②「業務日報」（対象期間: 今日）:
  【{{date}}業務報告】
  ■今日やったこと: 計{{today.totalHours}}h
  {{today.workLog}}

  ■勉強になったこと


  ■明日やること
  {{next.tasks}}


  ■連絡事項


  ■感想


テンプレートエディター:
- テキストエリアで本文を自由に編集できる
- エディター横の変数パネルに使用可能な変数を一覧表示する
- 変数をクリックするとカーソル位置に自動挿入される（シンタックス入力不要）
- プレビューボタンで実際のデータを差し込んだ表示を確認できる
```

#### FR-20 差し込み変数

```
テンプレートで使用できる変数（プレースホルダー）の仕様:

| 変数 | 差し込まれる内容 |
|------|----------------|
| {{date}} | 生成日（例: 2026/05/23） |
| {{period.start}} | 対象期間の開始日 |
| {{period.end}} | 対象期間の終了日 |
| {{today.totalHours}} | 今日の合計作業時間（例: 8.0） |
| {{today.workLog}} | 今日の作業ログ（プロジェクト別・工数付き・サブタスク含む） |
| {{today.plan}} | 今日予定のタスク一覧（期限日が今日 または ステータスが進行中、プロジェクト別・サブタスク含む） |
| {{today.completed}} | 今日完了したタスク一覧（箇条書き） |
| {{today.inProgress}} | 今日作業中のタスク一覧（箇条書き） |
| {{assigned.tasks}} | 担当タスク一覧（プロジェクト別・進捗%付き） |
| {{next.tasks}} | 未着手・次にやるタスク一覧（期限が近い順） |
| {{projects.summary}} | プロジェクト別の完了数・進捗率サマリー |
| {{period.completed}} | 対象期間内に完了したタスク一覧（週報・月報用） |

出力フォーマット仕様:
{{today.workLog}} の出力例（プロジェクト間に空行なし・コンパクト表示）:

    ○ ClaudeCode自走基盤設定
    ○ 開発
    ○ Vercel設定

{{today.plan}} の出力例（プロジェクト間に空行）:
  DWAI
  ● Vercelについて調査

  Aiエージェント課題
  ● 専用アプリ開発
    ○ ClaudeCode自走基盤設定
    ○ Vercel設定
```

## 3. 非機能要件

### 3.1 パフォーマンス

| 指標 | 目標値 |
|------|--------|
| 起動時間（コールドスタート） | p95 < 2 秒 |
| タスク一覧描画（1,000 件） | 60fps 維持 |
| 全文検索（5,000 件） | p95 < 200ms |
| 同期処理（1 接続あたり 100 タスク） | 5 秒以内 |
| アイドル時メモリ使用量 | < 300MB |

### 3.2 セキュリティ

- API トークン・OAuth トークンはすべて macOS Keychain に保管（平文ファイル禁止）
- 外部 API への通信は HTTPS のみ
- ログにトークン・個人情報を含めない
- アプリ終了時に認証情報をメモリからクリア

### 3.3 可用性

- ローカルファースト：ネットワーク不在でもコア機能が完全動作
- 外部 API 障害時もアプリは継続動作（同期失敗の通知のみ）
- 各外部 API のレート制限に対応したリトライ（Exponential Backoff）

### 3.4 互換性

- 最低 OS: macOS 14 Sonoma（SwiftData 採用のため。ADR-001 参照）
- Universal Binary（Intel + Apple Silicon 両対応）
- 配布形式: 未署名 .dmg（MVP）。初回起動時はユーザーが「開発元未確認」の許可操作を行う前提

### 3.5 スケーラビリティ

- 最大データ量（快適動作保証）: プロジェクト 50 / リスト 500 / タスク 10,000

### 3.6 アクセシビリティ

- VoiceOver 対応（SwiftUI 標準サポートを活用し主要 UI にラベル付与）
- キーボードのみで全主要操作が完結

### 3.7 国際化

- 言語: 日本語 / 英語（システム言語に追従）
- 日付・時刻フォーマット: システム設定に追従

## 5. 技術スタック

| 項目 | 内容 |
|------|------|
| 言語 | Swift 5.9+ |
| UI フレームワーク | SwiftUI |
| 永続化 | SwiftData |
| 認証情報保管 | macOS Keychain Services（Security.framework） |
| 外部 API - Notion | Notion API v1（Integration Token 方式） |
| 外部 API - Google | Google Sheets API v4（OAuth 2.0 Desktop App フロー） |
| 最低 OS | macOS 14.2 Sonoma（SwiftData 採用のため。ADR-001 参照） |
| バイナリ | Universal Binary（Intel + Apple Silicon） |
| 配布 | 未署名 .dmg（MVP） |
| Xcode | 15.2+ |

### アーキテクチャ方針

- **ローカルファースト**: 外部 API は同期時のみアクセス。コア機能はオフラインで動作
- **プラグイン型インテグレーション**: `IntegrationProvider` プロトコルで各ツールを抽象化。新ツール追加時はプロトコル実装とカタログへの登録のみで対応可能
- **接続（Connection）モデル**: ツール種別 × N 接続の構造を基本とする。`connectionId + externalId` を複合キーとして外部タスクを一意に識別
- **外部タスク統合モデル**: タスクに `connectionId` / `externalId` / `externalUrl` を持たせ、手動・外部を統合管理
- **Keychain 専用ストア**: シークレット管理を単一レイヤーに集約し、接続ごとにスコープを分離

## 6. リスクと対策

| # | リスク | 影響度 | 対策 |
|---|--------|--------|------|
| R1 | 未署名アプリで Keychain プロンプトが毎回出る可能性 | 中 | テスト後に問題なければそのまま。問題があれば暗号化ファイルで代替 |
| R2 | Notion API レート制限（3 req/sec） | 中 | Exponential Backoff + リトライ実装 |
| R3 | Google OAuth でのリダイレクト URI ハンドリング | 中 | カスタム URL スキーム登録（未署名アプリでも動作確認済み） |
| R4 | SwiftData の複雑クエリ制限 | 低〜中 | 複雑なクエリは Core Data 直接呼び出しにフォールバック検討 |
| R5 | 外部タスクの ID 衝突 | 低 | 複合キー（connectionId + externalId）で識別 |
| R6 | Google スプレッドシートのフォーマット多様性 | 中 | 列マッピング設定 UI でユーザーが対応列を指定できるようにする |

## 7. 用語定義

| 用語 | 定義 |
|------|------|
| プロジェクト | タスクをグループ化する最上位の概念 |
| リスト | プロジェクト配下のタスクグループ（例: 今日 / 今週 / バックログ） |
| インボックス | 外部から取得したタスクの受け取り専用リスト。固定的に存在し削除・リネーム不可 |
| タスク | 実行可能な作業単位。配下にサブタスクを持てる |
| サブタスク | タスクの配下にある細かい作業単位。タイトルと完了フラグを持つ |
| 作業時間 | その日にタスクに費やした時間（h単位、0.5h刻み） |
| 完了フラグ | タスクの完了/未完了を示すブール値（isCompleted）。ステータス「完了」と連動 |
| タグ | プロジェクト横断でタスクを分類するラベル |
| ステータス | タスクの進行状態（未着手/進行中/レビュー中/完了/保留） |
| 進捗度 | 0〜100% で表現するタスクの完了割合 |
| インテグレーション | 外部ツールとの連携機能の総称。ツール種別（Notion / Google スプレッドシート等）を指す |
| コネクション（接続） | インテグレーション内の具体的な接続設定1件。1 つのインテグレーションに N 個設定可能 |
| 外部タスク | 外部ツール（インテグレーション経由）から取得したタスク |
| 手動タスク | アプリ内で直接作成したタスク |
| レポートテンプレート | 差し込み変数を含む再利用可能なレポートのひな形 |
| 差し込み変数 | テンプレート内でタスクデータを自動展開するプレースホルダー（例: {{today.completed}}） |
| 日報 | 当日の完了・進行中タスクをまとめたレポート |
| 作業報告 | 指定期間の完了タスクを集計したレポート |
